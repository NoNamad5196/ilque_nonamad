## Planning Engine

`lib/v2/scheduler.ts`는 외부 호출 없는 순수 함수다.

1. 목표와 개별 퀘스트 중 더 이른 마감일까지 남은 날짜와 작업량, 이월 횟수로 우선순위를 정한다.
2. 사용자의 시간대에서 학습 가능 구간을 만든다. 고정 일정의 합집합을 제외하고 휴식 간격을 확보한다.
3. 최근 14일의 완료·미루기·제외·미완료 기록으로 학습 예산을 보정한다. 데이터가 3건 미만이면 기본 예산을 사용한다.
4. 실제/예상 시간 비율의 중앙값을 0.65–1.8배로 제한해 작업 길이를 보정한다. 완료된 오늘의 실제 시간은 남은 예산에서 차감한다.
5. 향후 14일에 마감 이전의 연속 빈 구간을 찾아 배치한다. 들어가지 않는 작업은 미배정으로 남기고 조정 이유를 설명한다.
6. 직접 고정한 시각은 유지한다. 충돌·지난 시각·마감 초과는 경고로 알린다.

`lib/v2/commands.ts`의 완료·완료 취소·미루기·제외/복구·수정·목표 변경·설정 변경은 동일한 스케줄러를 호출한다. 화면을 불러올 때 LLM을 호출하지 않는다. AI는 사용자가 요청할 때 목표의 남은 학습량과 기존 작업·완료 상태, 연결된 자료를 받아 작업을 분해한다. 사용자가 검토·수정·적용한 작업만 저장한다.

Calendar 동기화는 고정 일정을 갱신한다. SQL/공부/학습/복습/코테/알고리즘/스터디 또는 `#study`, `#학습`이 포함된 시간 일정은 고정 학습 퀘스트로 연결한다. 일반 회의·약속은 학습 작업으로 변환하지 않는다. 동일 Calendar 이벤트는 동일 퀘스트에 대응한다. 완료한 작업과 직접 수정·미룬 작업은 동기화가 덮어쓰지 않는다. 취소된 자동 학습 일정은 제외 상태로 남긴다.

## 저장 모델

`Workspace`에는 목표, 퀘스트, 자료, 주간 미션, 설정, Calendar 스냅샷, 계획 결과, 활동 이력이 있다. 토큰과 API 키는 들어가지 않는다.

### Supabase (기본)

기존 `user_goals.plan_json` JSONB를 재사용한다. 사용자당 하나의 비활성 행(`category=__workspace_v2__`, `is_active=false`)에 V2 문서를 보관한다. 결정론적 UUID로 중복 초기화를 막는다. 업데이트는 `user_id`, 행 ID, 이전 `revision`을 동시에 비교한다. 충돌 시 HTTP 409로 거부하며 조용히 덮어쓰지 않는다.

최초 조회 시 기존 목표/수동 퀘스트/완료 이력을 가져오고, 첫 수정 시 V2 상태를 저장한다. 원본 V1 행은 삭제하지 않는다. 기존 완료 XP는 `baseXp`로 보존한다. 기존 스키마를 그대로 활용해 필수 DDL 마이그레이션을 피한 개인 사용 MVP 결정이다. 데이터가 커지면 전용 테이블과 트랜잭션 RPC로 분리하는 것이 후순위다.

### 파일 (명시적 로컬 모드)

`npm run dev:local` 또는 `ILQUE_STORAGE=file`로 켠다. `.local-data/<사용자ID 해시>.json`에 저장한다. 파일 잠금, 버전 비교, 임시 파일 교체로 원자적 저장을 수행한다. 파일 모드는 지속 디스크가 있는 로컬 서버용이다. Vercel 등 일시 파일 시스템에는 사용하지 않는다. Supabase 실패 시 자동 전환하지 않으며, 화면에 저장 위치를 표시한다.

### 체험

`/demo`는 예시 데이터와 브라우저 localStorage만 사용한다. 인증 우회 API나 테스트 로그인 경로는 없다. 실제 계정 데이터와 섞이지 않는다. UI에서 체험 모드를 항상 표시한다.

## 인증·연동 경계

- 인증된 API는 세션의 subject만 사용자 ID로 사용한다. 요청 본문의 사용자 ID를 신뢰하지 않는다.
- JSON 쓰기 API는 교차 Origin을 거부한다. 만료/위조 세션은 401이다.
- 이전 V1 쓰기 API는 인증 후 410을 반환한다. 오래된 화면이 별도 저장 경로로 XP나 계획을 변경할 수 없다.
- 전역 Notion integration은 `ILQUE_NOTION_OWNER_EMAIL`과 일치하는 계정만 사용할 수 있다. 다른 계정에 개인 자료실을 노출하지 않는다.
- AI/Calendar 요청에는 시간 제한이 있고, AI 비정상 출력과 HTTP 오류는 기존 계획을 보존한다.
- Calendar 연결 실패 시 저장된 스냅샷을 유지하고 경고를 표시한다.
- Next.js 15.5.25 / NextAuth 4.24.15로 보안 패치를 적용했다. Async Request API 변경은 [Next.js 공식 업그레이드 지침](https://nextjs.org/docs/app/guides/upgrading/version-15)을 따라 반영했다.

## 알려진 범위

- 자동 배치 탐색은 14일이다. 작업의 자동 쪼개기, 선후행 의존성, 다중 캘린더, 반복 주간 가용 시간은 다음 단계다.
- Notion은 개인 integration 한 개를 사용한다. 사용자별 OAuth와 대용량 기록 동기화는 포함하지 않는다.
- 파일 ↔ Supabase 자동 병합은 없다. 데이터 내보내기를 제공한다.
- 외부 설정 복구와 실제 계정 연동 검증은 사용자 지시에 따라 이번 작업의 후속으로 남겼다.
