# ILQue V2 검증 기록

검증일: 2026-09-11. 브랜치: `redesign-v2`. Windows / Node.js 24 / Next.js 15.5.25 / Chrome에서 확인했다.

## 결과

| 검증                   | 결과                                                      |
| ---------------------- | --------------------------------------------------------- |
| `npm test`             | 38개 통과, 실패 0                                         |
| `npm run build`        | 성공: 컴파일, 타입 검사, 페이지 생성, 최적화 완료         |
| `npm run typecheck`    | 성공                                                      |
| `npm run test:api`     | 프로덕션 서버에서 17개 통과(상위 테스트 1 + 세부 검증 16) |
| 의존성 감사            | 패치 적용 후 알려진 취약점 0                              |
| `git diff --check`     | 공백 오류 없음                                            |
| 프로덕션 브라우저 콘솔 | 오류 로그 없음                                            |

프로덕션 서버는 `ILQUE_STORAGE=file`로 시작했다. HTTP 테스트는 테스트마다 고유한 가상 subject를 사용해 서버 API와 실제 파일 저장을 검증한다. 테스트 파일은 실행 후 정리한다. Google OAuth 성공을 흉내 내는 공개 로그인 경로나 인증 우회 기능은 추가하지 않았다.

## 자동 검증 범위

- **배치:** 고정 일정 합집합, Calendar 충돌, 휴식 시간, 종일 일정, 하루 예산, 미배정 처리, 결정론성.
- **마감:** 목표와 개별 퀘스트 중 더 이른 날짜, 마감 초과 방지, 지난 마감, 목표 변경 후 재배치.
- **재계획:** 완료·취소·미루기·제외·복구, 미완료 이월 한 번 기록, 실제 시간이 길거나 짧을 때 길이 보정, 최근 낮은 완료율.
- **Calendar:** 학습 일정 구분, 자기 일정과의 중복 충돌 방지, 시간 변경, 취소/복원, 직접 수정·미룬 작업 보존, 최초 연결의 지난 일정 제외, 주간 미션 중복 방지.
- **시간대:** 한국 자정, 미국 DST의 23/25시간 날짜, 지난 스트릭 만료, 잘못된 날짜/시간대 입력 거부.
- **AI/외부 오류:** HTTP 429/503, 비정상 JSON, 빈 작업, 시간 범위 초과, 과도한 작업 수, AI가 지정한 XP/시각 제거. Calendar 실패를 빈 성공 결과로 처리하지 않음.
- **인증/저장:** 미인증·위조 세션 401, 다른 계정 조회 분리·수정 거부, 브라우저 세션에 토큰 비노출, 교차 Origin 차단, Notion 소유 계정 제한, 클라이언트 XP 거부, 동시 수정 한 요청만 성공, 중복 완료 보상 방지, 실제 디스크 재조회, 이전 쓰기 API 차단.

Calendar와 Gemini의 성공/실패 응답은 단위 테스트에서 제어했다. 실제 운영 서비스 응답을 검증했다고 해석하면 안 된다.

## 실제 브라우저 QA

개발 서버에서 조작한 후, 빌드된 프로덕션 서버에서도 페이지 로딩·저장 데이터 유지·콘솔을 재확인했다.

| 흐름      | 확인한 동작                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 퀘스트    | 추가 → 실제 40분으로 완료 → 경험치 240→270 → 새로고침 후 완료 유지 → 완료 취소 270→240 → 제목/예상 시간 수정 → 다음 날로 미루기 |
| 목표      | 목표 생성 → 전체 학습량 180분에서 240분으로 수정 → 마감일 유지                                                                  |
| 주간 미션 | 제목과 주간 완료 목표 8개 저장 → 3/8 진행률 표시                                                                                |
| 자료      | 링크·요약·목표 연결 저장 → 해당 자료로 퀘스트 생성                                                                              |
| 설정/계획 | 하루 150분·휴식 5분 저장 → AI 계획 화면의 입력 요약 반영                                                                        |
| AI 화면   | 체험 모드에서 실제 연동이 필요하다는 오류를 명시하고 가짜 계획을 만들지 않음                                                    |
| 기록      | 완료/취소의 +30/-30 경험치, 미루기·수정·자료·목표 이력 표시                                                                     |
| 탐색      | 오늘·퀘스트·목표·주간 미션·학습 자료·진행 기록·AI 계획·설정 이동                                                                |
| 모바일    | 390×844, 메뉴 열기/화면 이동, 퀘스트 폼 스크롤·하단 버튼, 화면 밖 가로 넘침 없음                                                |
| 태블릿    | 768×1024, 퀘스트 카드와 사이드바 시각 점검, 가로 넘침 없음                                                                      |
| 데스크톱  | 1440×1000, 오늘의 주요 퀘스트·성장 기록·타임라인 시각 점검, 가로 넘침 없음                                                      |

반응형 QA 중 보조 글자 크기·색 대비, 모바일 사이드바 숨김, 대화상자 포커스를 보완했다. 개발 중 생성 파일이 갱신될 때 일시적 오류가 있어 개발 서버를 종료하고 프로덕션 빌드·별도 타입 검사·프로덕션 브라우저로 최종 확인했다.

## 사용자 지시로 후속에 남긴 외부 검증

실제 Google 로그인 시 `redirect_uri_mismatch`를 확인했다. 현재 Supabase 프로젝트 호스트는 DNS `ENOTFOUND`로 연결할 수 없었다. 사용자가 **“외부 설정은 나중에, 구현과 로컬 검증을 계속해 주세요”**라고 지시했다.

따라서 실제 Google 로그인 성공, 실제 계정 Calendar 읽기, 활성 Supabase에 저장 및 V1 이전 데이터 가져오기, Gemini/Search Grounding과 Notion 실제 연동은 후속 검증이다. 이 문서는 해당 항목의 성공을 주장하지 않는다. 필요한 설정과 실행 방법은 [README](../README.md), 후속 목록은 [TODO](../TODO.md)에 있다.
